## Actions 训练时间（2026-10-23 真机确认）

用户确认 Actions 的 Workouts 输出提供 Identifier、Workout Type、Start Date、End Date、Duration、Elapsed Time 等属性，Start Date/End Date 可格式化为 ISO 8601。

保留已有 `dates`、`values` 和来自网页的 `workout_id`。无需选取某一条 Apple 训练，直接引用完整 Workouts 列表，按相同顺序提取三个属性：

| 上传 JSON 文本字段 | 整个 Workouts 列表的属性 |
|---|---|
| `apple_workout_id` | Identifier，全部用换行符合并 |
| `started_at` | Start Date，全部格式化为 ISO 8601 后用换行符合并 |
| `ended_at` | End Date，全部格式化为 ISO 8601 后用换行符合并 |

三份列表必须等长且一一对应，最多 5000 条。也支持三个 JSON 数组，或原来的单条值。无需手工拼接 JSON。服务器只取 OpenGym 所选训练日期上的 Apple 训练；当天多场时全部关联到这条记录，按这些时段的并集截取心率，不计入时段之间的心率。其他日期训练只在内存中验证，不保存。界面会提示关联了当天多场训练。如果当天有多个独立 OpenGym 记录，不应将相同整日结果重复关联到各条记录；当前批量模式按用户明确选定的目标记录关联当天全部 Apple 训练。

Apple 训练标识与 OpenGym 的 workout_id 不同。日常版显式上传 `sync_workout_time: "true"`，在心率匹配成功后，同时更新目标训练的 start/end，保留组数、重量和备注。最初的时间保存在 appleHealthTime.previous；revision、write ID 和字段时间戳保证离线旧数据合并后保留更新时间。旧版不传此字段时，继续只保存独立的 Apple 窗口。同日多场时记录最早开始到最晚结束的跨度，各时段另存，心率仍排除间隔；跨度不是扣除暂停后的有效时长。重复上传相同训练集合会去重；已关联的 Apple 集合或时间变化时返回冲突，需先导出/删除旧心率再重关联。不能用 Duration 反推结束时间。

## 首次设置

1. 点「创建上传凭证」，将完整 `Bearer …` 复制到 iPhone 快捷指令的 Authorization 标头。凭证只显示一次，长期有效，可手动撤销或替换，仅能上传心率及所选训练的 Apple 起止时间；重新创建会替换旧凭证，撤销立即生效。退出所有设备或停用账户也会使凭证失效。
2. 快捷指令命名为 **OpenGym 心率同步**，上传 URL 改为 `https://gym.example.com/api/heart-rate/import`（其他部署使用自己的地址）。保留已验证的日期和值提取逻辑。
3. 从「快捷指令输入」获取字典，分别提取 `date`、`workout_id`。网页会以 JSON 文本传入：

   ```json
   {"date":"2026-10-22","workout_id":"该训练的真实 ID"}
   ```

4. 健康样本类型为心率，不分组、不限数量，按开始日期升序。日期筛选使用 `date` 对应日期；若系统选择器不能引用变量，日常使用「过去 2 天」，更早记录手动选日期。无需精确到时分秒。
5. 获取这份样本的全部「开始日期」，格式化为 ISO 8601，保留时区，以换行符合并为 `dates`。再从**同一份健康样本**获取全部「值」，用换行符合并为 `values`。
6. 获取 URL 内容，方法 POST，请求体选 JSON：`dates`、`values` 两个文本字段，分别引用合并结果；`workout_id` 文本字段引用输入字典中的训练 ID。添加 Authorization 标头，最后显示返回结果。

首次执行按提示允许读取心率和访问服务器。不要分享含上传凭证的快捷指令。手机保持解锁；手表到 iPhone 同步有延迟时，稍后再次同步可以补齐。

## 每次使用

在 iPhone 网页打开一条已完成训练 → 点「在 iPhone 同步心率」→ 系统启动快捷指令 → 返回训练详情自动刷新，也可手动点「刷新心率」。Safari/PWA 可能要求确认打开快捷指令；这不是持续后台同步。

API 响应 `ok: true` 且 `storedWorkouts: 1` 表示已保存。日常版成功时不显示 JSON；`timeSynced: true` 表示时间也已写回，重复同步可以不产生新 revision。`added: 0` 且已有保存记录，通常表示再次上传没有新样本。只有 `ok: true` 不能代表匹配成功，应检查 `storedWorkouts`、`unmatched`、`ambiguous` 和 message。

没有传 `workout_id` 的上传按时间匹配已完成训练；同一时刻只属于一条训练才会保存，重叠部分不猜测。推荐通过网页入口明确指定训练。

## 数据含义与管理

- 仅保存训练时间范围内的匹配心率，其他样本不落盘。日期与数值列表必须一一对应；原始健康样本类型、设备 UUID、HealthKit 样本 UUID 不在此快捷指令协议中，因此来源显示为 Apple 健康，不能保证每条都来自 Apple Watch。
- 绝对时间戳和心率值保存为每条训练的独立数据，重复的时间和值不会重复计入；不同心率但相同时间保留。不是医疗分析，不自动调整力量训练计划。
- “样本平均”为算术平均，不能直接等同 Apple 的训练统计。曲线显示时保留峰值，超过两分钟的缺测断开；降采样只用于绘图，导出数据完整。
- 修改训练日期或时长不会平移心率。界面只显示新训练窗口中的数据，并提示时间变更；导出保留已导入的原始样本。旧版客户端上传训练状态不会覆盖心率。
- 训练详情可以单独「导出心率」或「删除心率」。删除普通训练时清理相应心率文件，重置账户数据会清理心率及凭证；删除账户同样清理。Plugin 删除训练后也会清理。
- 原始心率位于服务器 `DATA_DIR/heart-rate/`，权限为目录 0700、文件 0600，随现有加密服务器备份保存。App JSON／媒体 ZIP 备份不含此目录，应使用单独心率导出或服务器备份。旧备份仍按服务器备份保留规则存在。
- 临时 `/probe/` 不写入账户；需要改用正式接口重新上传，之前的验证数据不会凭空出现在曲线中。

## API 与原生扩展

账户认证：GET/POST/DELETE `/api/heart-rate/connection`；GET/DELETE `/api/heart-rate/workout?workout_id=…`；GET `/api/heart-rate/export?workout_id=…`。

专用上传认证：POST `/api/heart-rate/import`，`Authorization: Bearer ogh_…`。支持换行文本列表或 `{samples:[{at:"带时区的 ISO8601",bpm:110}],workout_id:"…"}`，每请求最多 20000 条、最多三天跨度，每训练最多 50000 条。错误以 code 和说明返回，不回显原始样本或凭证。

未来 iOS 原生 HealthKit 读取模块可以发送同样的样本协议，复用验证、时间匹配、存储、去重、导出及网页展示。原生样本 UUID、设备来源和删除同步需要另行扩展协议；当前并未实现 HealthKit 原生读取或锁屏后台同步。

## ChatGPT 训练记录直接保存

部署变量 `PLUGIN_TRAINING_AUTO_SAVE_USER_IDS` 是明确选择启用的账号 ID 列表。仅该账号的普通训练记录新增、修正可返回 `authorization.requires_user_confirmation: false`；模型先验证草稿，再直接保存精确草稿并汇报结果，无需额外的确认回复。即使字段齐全，遇到含糊表述、疑似笔误、异常数值、单位／单双侧冲突、与近期训练不一致等情况，也必须先提出具体问题，不能静默改值或猜测。异常不等于错误，应由用户澄清。preview 支持 `review_questions`；非空时关闭直接保存并要求澄清后重新预览。没有该字段也不代表已消除疑问，模型仍须审查原始表述和相关上下文。删除、撤销、计划、身体指标、长期个人背景和常驻动作备注不适用。账号隔离、草稿绑定、版本冲突检测和 ChatGPT 自身工具授权保持生效。

服务端更新后，ChatGPT 缓存的工具说明可能仍写着旧的确认规则；需要在该应用详情页刷新工具、描述及 server instructions。此次发布确认服务端偏好已启用，但现有会话工具定义仍为旧描述；电脑控制工具禁止操作当前聊天应用，因此未能代点客户端刷新。没有修改应用权限或 App 绑定，也没有通过改包来绕过刷新。

## Plugin 分析与体重

Plugin 的训练详情、历史清单和训练区间统计读取同账号的心率摘要，使用 `training:read` 权限；不向模型返回原始样本。包含样本数、均值、范围、起止时间、缺测信息及缺失状态。均值为记录样本的算术平均，不保证与 Apple 的训练平均一致；不能由它推断肌肉刺激、自动增加训练重量或判定恢复。比较时应结合训练内容、时长、组间休息、RPE/RIR，先检查采样缺失。

Plugin 已有 `get_body_metrics`、`preview_body_update`、`save_body_update`，需独立 `body:read` / `body:write` 授权。支持按日期记录体重、目标体重、围度和体脂率，并提供每周平均体重。保存前展示预览并明确确认；无需新建训练。可以说「记录今天体重 72.4 kg」。这次未加入 Apple 健康体重自动导入。

其他值得后续接入的指标：每日睡眠时长、静息心率、HRV，适合存为独立按日数据；HRV 保留测量方法、时间和单位，睡眠需处理跨夜及重复来源。优先比较个人趋势，不生成没有校验依据的恢复分数。步数可作为活动量背景，估算热量不宜作为力量训练质量指标。

参考：[Apple 测量准确性](https://support.apple.com/en-us/105002)、[Apple Vitals 与夜间指标](https://support.apple.com/guide/watch/vitals-apd15aa7ed96/26/watchos/26)、[ACSM/ESSA 运动强度共识（RPE 可辅助监测抗阻训练强度）](https://www.jsams.org/article/S1440-2440%2824%2900559-0/pdf)。这些资料支持观察指标及解释限制，不代表自动恢复评分已得到验证。

## 2026-10-26：网页启动，无需手动填写凭证（本地，尚未部署）

从网页下载新版并替换同名快捷指令后，登录 OpenGym，直接点击同步即可。无需编辑服务器地址或 Bearer 文本。
安装旧快捷指令的用户仍需更换新版文件；仅更新网页无法改变手机中已安装的快捷指令。

网页调用 `POST /api/heart-rate/shortcut-session`，由账户会话自动创建 30 分钟的临时 `ogs_` 授权，随 `shortcuts://run-shortcut?...&input=text&text=...` JSON 参数传入。
参考 [Apple 快捷指令 URL scheme](https://support.apple.com/guide/shortcuts/apd624386f42/ios)。
授权仅允许 POST 心率待补查询、心率上传和日常健康上传，不能读导出记录、删除数据、操作账户或再签发授权。
服务器只保存令牌摘要、账户、会话版本与到期时间；每账户最多保留 10 个并行启动授权，签发时清理过期文件。
全部注销、账户停用会使授权失效。网页检测启动期间的账户切换，不把旧账户授权交给快捷指令。
既有 `ogh_`、`ogd_`、`ogw_` 客户端保持兼容，自动启动不会替换或撤销其凭证。
网页不再展示凭证编辑器；旧 API 供已有客户端继续使用。
