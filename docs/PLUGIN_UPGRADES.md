# 官方 App、服务器与私人 Plugin 的升级

当前验证基线：OpenGym 1.4.1，提交 `464355ef43d4c8f8a4e0bb6db9c2af7f240593b5`；私人 Plugin 源码 v0.7.0。不把“当前安装版本”当作未来最新版本或兼容承诺。

## 各部分独立更新

- 官方 Android APK：安装在手机上的界面、离线存储、训练及合并代码。更换 APK 不会自动升级服务器。
- 服务器 API：账户、配对、存储、并发修订和同步接口。上游数据或 API 格式改变时，必须核对旧服务器与新 App 的兼容性。
- 网页/PWA：服务器托管的前端资源，更新服务器网页镜像后在浏览器加载。当前仍保留此前的登录/邀请接入改动，与训练开练无关。
- 私人 Plugin：`api/plugin/`、API 的少量接入代码、构建镜像及反向代理配置。ChatGPT 指向的 MCP URL 可以保持不变，但接口变化后需要刷新客户端工具元数据。

不是每次 APK 更新都必须同时更新 API。如果上游变更仅涉及界面或不影响已有接口，通常可以独立更新；不能事先保证任意未来版本组合。实际升级以对应发行说明、数据迁移及回归结果为依据。

## 当前定制边界

v0.5.1 已撤回 v0.5.0 对训练解析、开练、同步库、单位换算和训练相关界面的改动。官方 APK 不需要包含我们的源码。

扩展代码集中于 `api/plugin/`，接入代码直接维护在 `api/server.js` 中。早期 `integration.patch` 已落后于健康数据、营养与手表绑定接入，现已移除；升级时使用 Git 对比基线与当前分支的实际代码：

```sh
git diff 464355ef43d4c8f8a4e0bb6db9c2af7f240593b5 HEAD -- api/server.js api/plugin frontend/src web
```

1. 在同一 API 写入进程挂载可选 MCP/OAuth 路由；仍使用账户原持久化、修订和缓存。
2. 在普通客户端 PUT 写入时保护 Plugin 专属背景与版本字段，避免旧客户端整份文档回写丢失扩展数据；显式账号重置允许清除。

`frontend/src/lib/` 与目录资源在服务器镜像中用于复用纯计算器；v0.6.0 为共享动作搜索增加别名匹配，并让新版网页动作列表和选择器隐藏归档项。服务端仍保留归档动作供现有计划和历史解析。无需定制 APK，但旧 APK 不会按归档状态隐藏动作，也不识别新增别名搜索。升级上游后仍要验证函数导出、字段含义及记录格式。纠错的保留重量回退适配位于 Plugin 内，与上游编辑器做行为对照测试。

此外，还要保留先前的私人部署与朋友接入改动：网页登录/邀请、nginx 路由与安全配置、Docker 构建覆盖层及部署 Compose。不能只保留 MCP 地址而删除这些实际服务代码。

## 每次上游升级的步骤

1. 保留当前工作区改动，将扩展和所需补丁纳入自己的分支/仓库或可恢复源码快照。不要在有未提交定制代码时直接覆盖工作区。
2. 检查上游对应版本的发行说明、同步/API 改动和数据迁移，选择要验证的官方 App/API/Web 版本组合。不要默认 `latest` 与旧 APK 兼容。
3. 在隔离分支合并上游。通过 Git 合并并检查 API 接入位置的冲突。网页接入改动同样要检查。不能拿旧版完整 server.js 覆盖新版 server.js。
4. 更新 API/Web 构建基线，重新构建带 Plugin 的镜像。直接换成官方 API 镜像会丢失 MCP 路由及扩展字段保护。当前 Compose 使用内容 ID 和 pull_policy=never，不是上游指南中直接 docker compose pull 的部署。
5. 跑 Plugin 测试、真实双账号隔离和配对手机 HTTP 测试、官方客户端合并算法的离线/回写测试、上游同步与相关训练计算器测试，以及前端构建。模型建议和统计继续复用该基线的计算函数。
6. 用无真实个人数据的测试账户验收：手机旧版本仍能拉取补录记录、离线改动能合并、重要背景不丢失；如准备更换 APK，再测新版本。不能把容器测试等同于实体手机验收。
7. 完成加密一致性备份，保留旧镜像和 Compose，部署已测试的固定镜像，验证健康、MCP 工具与原连接。数据格式若迁移，必须另外验证回退策略，不能只换回旧镜像。
8. 必要时再更新手机 APK；工具定义变化后刷新 ChatGPT 原连接，权限范围新增时重新同意 OAuth。不需要因此创建新 Plugin 或更换 MCP URL。

这种方案仍有维护成本：升级时要保留并验证我们的服务端扩展。它避免了为这项训练助手功能维护另一套安卓 App，但不意味着上游升级可以无人审核或永远自动合并。
