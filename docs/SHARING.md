# 分享版本与隐私检查

## 交付方式

分享 `https://github.com/bitA23187/opengym-agent`，首次版本固定为 `agent-v0.1.0`。
仓库已按维护者要求公开；朋友可直接克隆，无需协作者邀请或 GitHub 令牌，
再把 `docs/AGENT_DEPLOYMENT.md` 交给 Agent。自己的服务与数据仍需独立部署和授权。

分享仓库从清理后的源码快照开始，不继承私人开发历史。旧仓库保留为独立私有归档，
不要将归档仓库的访问权授予只需要这个项目源码的协作者。历史分支还原包只保存在
维护者本地，不作为 Release 附件或源码文件提交。

## 2026-10-26 检查范围与处理

- 检查旧远程的全部分支历史、交付源码、Git 忽略规则和 Docker 构建排除规则。
- 实际服务域名和私人插件安装链接已替换或删除；探针必须显式接收目标地址。
- Apple Team 已清空，个人 Bundle ID 改成 `com.example`；Watch 默认地址改为示例。
- 服务器镜像内容 ID、特定入口网段和备份远程默认值已改为通用示例或必填参数。
- 不分发原维护者签名的快捷指令容器；保留生成源码，由部署者自行生成与签名。
- 不纳入账号/训练/健康数据、`.env`、`agent.env`、证书、密钥、备份、原生构建产物
  与私人运维日志。单独许可的动作媒体也不纳入 Git。
- Gitleaks 在旧历史和交付源码各报告两类命中：CocoaPods 校验和、推送测试用公开
  常量。经人工复核未确认它们是真实秘密；保留原文件，不扩大扫描豁免。
- 共享仓库禁用 Actions，不自动发布镜像、镜像到上游或部署 Pages；定期依赖 PR
  暂设为 0。后续启用 CI 时逐项审查工作流、目标仓库与凭据范围。

此检查不构成“所有历史引用和第三方副本均已消失”的证明。旧仓库仍是私有归档；
真实令牌若曾进入 Git，需要单独撤销/轮换。公开 upstream 作者署名、第三方许可
与项目来源链接按原要求保留。

## 固定标签是什么

`main` 会继续变化，`agent-v0.1.0` 指向本次交付的一个确定 commit。双方报告问题时
提供这个标签与 `git rev-parse HEAD`，便能判断是否在讨论相同源码。修复后创建新标签，
例如 `agent-v0.1.1`，不删除或移动旧标签。此规则是维护约定，不等于 GitHub 已配置
不可变标签保护。源码固定也不等于基础镜像和构建依赖仓库永久不变；保留实际镜像 ID
和归档才能进一步复现运行环境。

## 后续维护

个人工作目录和分享版本分开维护。将需要交付的修改移到干净分享分支，复查配置与
Git diff，再提交、测试和打新标签。不要将私人分支、原始完整历史或本地备份用
`git push --all` / `--mirror` 推到分享仓库；只推明确审查过的分支与标签。

可让朋友将以下提示交给 Agent：

> 请部署这个仓库的 agent-v0.1.0 版本。先读 AGENTS.md 和
> docs/AGENT_DEPLOYMENT.md，检查我的环境，使用我自己的域名与账号配置。
> 先在本机验证并初始化所有者，再配置 HTTPS、启用插件；报告完成的检查、
> 已知限制和需要我提供的信息。不要访问原维护者实例或修改真实健康数据做测试。
