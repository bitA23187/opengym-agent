# 定制版 1.4.4 与 Plugin 0.9.0

2026-11-05，Asia/Taipei。根据 [上游评审](UPSTREAM_1_4_4_REVIEW.md) 选择性移植 v1.4.2–v1.4.4 的可靠性修复和训练后分析功能；保留本地营养、日常健康、结构化训练、OAuth/MCP 及独立 Watch 上传。应用 API/网页和原生源码版本为 1.4.4，Plugin 为 0.9.0。这是定制版本，不宣称包含上游所有功能。

## 用户可见变化

- Stats 分为概览、身体、力量和强度，支持分区跳转；保留睡眠与营养。
- 每周肌群工作组数与可调整目标、历史逐组对比、逐组备注、相对体重力量、体重变化速度、可选力量等级、周/月回顾。
- 称重可在同一天保存多次，带时间，可单独编辑、删除和撤销；可选择晨重、平均或最后一次作为图表的每日值。
- CSV 导出、回导和上游导入纠错；体重 CSV 保留每次称重。攀岩、分段次数和自定义观测的完整数据仍使用 JSON 备份，导出界面说明此边界。
- 上游动作主/次肌群纠错；不修改用户训练原始组次。肌群分布会根据新目录重新计算。
- 上游日期选择器用于称重和 CSV 范围；统计页的身体/相对力量采用独立中文措辞，避免混淆徒手训练。

## Plugin 体重功能已移除

体重、称重时间和目标体重只在网页/App 管理。`get_body_metrics` 不再返回体重、周均体重或目标体重，写入 schema 不再接受 `weight` / `target_weight`。服务端内部更新函数也拒绝这两项，旧客户端缓存的调用无法继续写入。

围度等身体测量保留，继续使用原来的 `body:read` / `body:write`。OAuth 权限文案已相应缩减；不扩权、不改变账号、授权、连接地址或 Plugin 身份，也不删除已有称重、目标或测量数据。

新增 `sets[].note` 及组备注局部纠错，支持完整导入、左右侧、助手增量会话与读取。原有直接保存策略、澄清问题、修订、幂等、账户隔离与撤销规则继续适用。宿主缓存工具定义时需要刷新原连接。

## 安全和数据完整性

- API base 同源限制、Passkey 登录来源校验、手机配对身份核验；保留设备会话类型和独立健康上传凭证。
- 推送订阅的归属、格式和大小限制，IPv6 内嵌私网地址检查；nginx 的 Plugin 路径也使用规范化后的代理地址。
- 提醒队列线性计算与缓存、提醒限流和停用账号检查、Owner/Admin 权限边界。
- 无变化保存不再使已删除训练在多设备同步时复活；助力器械的显式 target 不用于 1RM 估算。
- 原始称重兼容旧客户端；同步、单位换算和健康写入处理新称重明细。导入/健康来源的读数不会重新写回健康平台，删除单次读数也会清除对应的已写入副本。
- API、只读 MCP、私人 Plugin 的受影响依赖更新；Plugin/只读 MCP 迁移到 Zod 4，并适配自定义观测字典。固定锁文件和传递依赖覆盖。
- API 发布镜像直接使用当前源码和两个独立锁文件构建，不再继承旧版应用代码/依赖；保留可回退的旧镜像。

## 验证与部署

本次包含完整前端、API、Plugin、只读 MCP 回归，目录/翻译/接口文档生成检查，生产构建、原生工程接线和共享 Swift/Watch 协议检查。历史 Coach 测试采用推进中的固定测试时钟，避免七月的训练样例在十一月因十二周窗口自然过期；不改变生产的历史窗口策略。

界面使用合成账号数据，覆盖 320/375/414/768 像素与深浅主题。发布前在隔离 Linux 镜像运行服务端测试；创建加密一致性备份后更新固定镜像，验证健康、静态资源、MCP 工具元数据与匿名访问边界。部署证据和回退 Compose 保存在本地操作日志与忽略的 artifacts 中。

原生源码的版本标记已更新，服务器发布本身不会替换手机上已安装的 APK/IPA。原生健康后台调度和真实设备行为不能由网页或容器测试代替。
