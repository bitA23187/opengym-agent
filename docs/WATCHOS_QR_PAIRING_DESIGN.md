# Apple Watch 网页扫码绑定：可行性与设计

日期：2026-10-25（Asia/Taipei）。状态：0.2.0 已实现并完成本地验证；2026-10-26 已部署正式 API/Web，实体手表安装清单已确认 0.2.0（2）；手动打开与真实扫码验收待用户确认。

## 结论

推荐“手表显示二维码 → 任意手机相机扫描 → OpenGym 网页登录并确认 → 手表自动完成绑定”。
浏览器是首要入口，手机 OpenGym App 可在后续复用同一绑定协议；不要求安装手机 App，也不依赖 iPhone WatchConnectivity。
二维码承载普通 HTTPS 网页链接，适用于 OPPO、iPhone 或其他能扫码并打开网页的设备。
扫码授权的是 OpenGym 设备连接；HealthKit 的读取权限仍由用户在手表上单独授权。

## 建议交互

1. 手表点击“连接”，向指定 OpenGym 服务器申请短时有效的绑定会话。
2. 手表展示二维码、短校验码、服务器域名和倒计时；约 5 分钟过期，过期后手动刷新。短码也是扫码失败时的输入兜底。
3. 相机扫码打开该服务器的 `/#/watch-pair?code=…` 页面。未登录时先登录，然后保留绑定上下文返回此页。
4. 页面显示当前登录账户、待绑定设备名称、与手表相同的短码和授权范围。用户确认绑定；仅打开链接不能自动批准。
5. 手表在前台按约 5 秒间隔查询，处理等待、限速、拒绝、过期、成功状态。成功后自动保存账户 ID 和设备凭证到 Keychain，并显示已连接账户。
6. 返回首页后，由用户主动请求 HealthKit 授权、检查或同步数据。

设备名称是客户端提供的描述，不能把它当成硬件身份认证。网页需提示用户核对手边手表上的校验码。
手机与手表不必在同一个局域网，但二者都必须能访问同一个 OpenGym HTTPS 服务器。

## 首次服务器地址从哪里来

二维码不能解决未知服务器的发现：手表必须先知道请求发往哪里。

- **当前自用版本**：在构建配置中预设用户自己的 HTTPS OpenGym 地址。它不是秘密，应用内允许更改。用户可完全不用在手表输入地址、账户 ID 或凭证。
- **通用自托管版本**：保留首次填写/选择服务器地址的入口；后续仍由网页扫码完成账户绑定。
- 如要做到任意自托管实例也完全零输入，需要额外的引导发现/中继服务，或 iPhone companion 协助把地址送到手表。这是独立设计取舍，不在首版绑定中引入。

## 现有代码的可复用部分

- `api/server.js` 已有 `/api/pair/create`、`/api/pair/redeem` 的一次性短码、过期、登录会话和账户状态校验基础。
- `frontend/src/lib/remote.js` 已支持手机 App 用网页生成的短码登录，但其方向是“已登录网页发码 → App 输入”，与本方案相反；不能直接套用。
- 现有手机配对会兑换完整账户会话；手表只需健康上传权限，不应直接复用这类令牌。
- `frontend/src/App.jsx` 使用 HashRouter，未登录时显示 Login；需新增专用页面并确保登录/过期后正确恢复绑定上下文，不落入未知路由的首页跳转。
- `WatchSyncEngine`、`WatchStorage` 的配置验证、Keychain、连接 ID 与队列隔离可以保留。成功绑定时由服务端返回账户 ID，不再让用户手填。

## 本次实现的能力

1. **绑定会话**：分别生成仅手表持有的高熵领取秘密和可展示的短码。二维码里不包含长期上传凭证，也不包含能领取令牌的手表秘密。
2. **网页确认**：复用现有登录，批准操作使用受 CSRF 保护的 POST，校验短码、过期、会话状态及账户状态；GET 打开页面不绑定。绑定页面不加载第三方分析/二维码服务。
3. **设备凭证**：每块表独立的上传凭证，服务端仅保存长期凭证的摘要，绑定账户与撤销版本；权限限定为健康上传及必要的最小账户/待补查询。
4. **领取与重试**：只有持有手表领取秘密的一端可以领取；处理响应丢失、Keychain 写失败、应用退出、服务重启与重复确认。不能因一次响应丢失就永久卡死；绑定过期后能重新开始。
5. **设备管理**：网页列出已绑定设备，并允许单独撤销。删除 Watch 凭证不会影响 iPhone 或快捷指令。
6. **二维码展示**：可由自己的服务器生成二维码图片或矩阵，手表负责清晰显示；不要假定 watchOS 具备 iOS 上的 Core Image 框架。需在 Series 7 真机检验尺寸、留白、亮度与相机识别。

原有 `health-upload-credentials.js` 的 `issue()` 会先撤销账户旧健康凭证，不能拿它直接完成设备绑定。
新增设备凭证应与旧 `ogh_`/`ogd_` 凭证并存，现有快捷指令协议继续有效。

## 认证与生命周期要求

- 短码有效期 5 分钟，领取秘密至少 256 bit 随机；匿名申请、错误短码与轮询均需限速和总量上限。
- 扫码后展示目标账户，确认与手表短码一致；拒绝/过期/已被另一账户批准时不能继续换账户领取。
- 绑定与上传固定同一 HTTPS origin，不携带凭证跟随重定向。
- 前台等待配对即可，不为轮询开启虚假训练或保证后台运行；离开后显示可恢复或重新申请的明确状态。
- 服务端重启若采用内存会话，应明确让未完成会话失效、重新扫码；不影响已经绑定的持久设备凭证。
- 注销全部设备、账户停用和单设备撤销的语义必须与现有账户安全规则一致。
- 屏幕只展示扫码所需的短时信息；长期凭证不出现在二维码、地址栏、日志或网页中。

## 实施与验收顺序

1. 先实现设备凭证与绑定状态机的后端测试：错账户、过期、重复批准、领取秘密不匹配、限速、重启、撤销，以及旧快捷指令不受影响。
2. 增加移动浏览器绑定页：已登录扫码、未登录扫码后返回、切换账户、短码输入兜底、拒绝/过期状态。
3. 手表改为二维码连接首页，保留高级手动配置兜底；取消与换服务器时清理原绑定流程，不能串用旧队列。
4. 真机使用 OPPO 系统相机扫码，网页批准后，手表自动显示连接成功；确认可独立撤销该 Watch，iPhone 和快捷指令仍可用。
5. 另行取得用户在手表上的 HealthKit 授权，再验收真实健康数据上传。扫码绑定成功不能等同于已允许健康读取。

## 依据

该交互可参考 [RFC 8628 Device Authorization Grant](https://www.rfc-editor.org/rfc/rfc8628.html) 的双设备授权思路：显示校验网址/短码、浏览器登录并批准、设备持领取秘密轮询。若仅实现 OpenGym 自有绑定协议，应明确它不是完整的通用 OAuth 服务端实现。

原有方向：[Watch 开发文档](WATCHOS_DEVELOPMENT.md)、[独立上传调研](APPLE_WATCH_UPLOAD_RESEARCH.md)。

## 0.2.0 实施记录

已实现手表二维码与短码、网页登录与明确批准、前台领取、Keychain 保存与 ACK、设备列表和独立撤销；保留高级手动配置。自用构建预设 `https://gym.example.com`，可改服务器。服务端二维码使用随 API 分发的 lean-qr nano 2.7.3；没有外部二维码服务或新增 watchOS 框架。

接口均在 `api/openapi.yaml`：`POST /api/watch-pair/{start,approve,poll,ack,cancel}`、`GET /api/watch-pair?code=…`、`GET /api/watch-devices`、`POST /api/watch-devices/{verify,revoke}`。批准与设备管理依赖现有账户会话及 CSRF 防护；设备侧 start/poll/ack/cancel 不使用浏览器登录会话。

长期设备令牌 `ogw_…` 与旧快捷指令凭证并存。持久文件仅保存令牌摘要；短期领取秘密和可重发令牌仅存在服务器内存会话中。未 ACK 的凭证带绑定截止时间，服务重启后也会自动失效；完成 ACK 的凭证不受会话到期或重启影响。单设备撤销、全部注销、账户停用、账户“重置所有数据”会阻止相应 Watch 继续使用。

手表仅在前台等待；关闭页面或进入后台会暂停，重新打开可恢复。网络失败保留会话，重新点击“继续等待”；过期则重新生成。服务重启会终止未完成绑定，需要重新生成。异常情况下若服务器已 ACK 而手表未能清理本地领取记录，可在网页移除旧设备，再重新绑定。

验证结果与构建见 [0.2.0 交付记录](../artifacts/watchos/2026-10-25/qr-pairing-0.2.0/README.md)。本地浏览器检查使用临时合成账户；HTTP 测试覆盖批准、领取、ACK、上传和撤销。没有实际扫描实体手表屏幕，也没有读取或上传个人健康数据。真实相机识别、正式 HTTPS 链路和 watchOS 26.6 上的完整扫码流程仍待部署后验收。

## 0.3.0 界面与协议更新（本地，尚未部署）

手表仅显示 QR 和倒计时，网页要求确认刚扫描的是身边这块表，不再核对字母码。
已登录网页读取绑定请求后，服务端记录 `scanned`；设备轮询仍返回 `status: pending`，附加 `scanned: true`。
旧设备可以忽略附加字段。新设备在二维码中央显示等待指示，保存/ACK 成功后显示绿色勾约 1.3 秒，再回到首页。
相机仅识别二维码但尚未打开已登录网页时，服务端无法知晓扫码，因此不会提前显示等待确认指示。
连接页使用原生层级后退；离开页面暂停轮询并保留会话，返回后恢复。网络错误使用系统提醒重试。
过期会话在二维码上显示状态和重新生成操作，不再要求滚动或取消旧会话。
