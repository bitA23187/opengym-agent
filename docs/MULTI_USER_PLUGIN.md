# 多用户 OpenGym Plugin：隔离与朋友接入

调研与本地验证日期：2026-10-18。结论：同一个远程 MCP 服务可以供多位用户使用，每位用户分别完成 OAuth，服务端按授权对应的 OpenGym 用户读写数据。无需为每人部署一套服务。

v0.4.0 增加一次性注册链接、接入说明页、当前连接账号工具、授权账号提示和最终写入归属检查。没有公开发布到插件目录，也没有创建朋友的生产账号或生成生产邀请码。朋友的独立 ChatGPT 账号和 Android 真机尚未端到端验收；部署结果见本机运维日志 OPERATIONS.md（不纳入 Git） 的 v0.4.0 记录。

## 账号是如何对应的

朋友在自己的 ChatGPT 账号中连接 OpenGym，跳转到本站，登录**自己的 OpenGym 账号**并同意授权。该授权记录的 `uid` 决定以后所有工具的账号范围。

ChatGPT 账号与 OpenGym 账号是两套身份；不能根据聊天里自称的姓名、邮箱或 userId 选择账号。授权页显示当前 OpenGym 账号，应核对后再同意。每个人独立授权，不分享登录 Cookie、手机配对 Token、OAuth Token 或已登录浏览器。

此模式由用户在 ChatGPT 中发起对话与调用；OpenGym 服务执行训练工具，不需要保存用户的 OpenAI API Key 或额外代付模型请求。它不涉及在 OpenGym 网页里调用用户 ChatGPT 订阅的另一种集成。

官方要求私有数据和写入使用 OAuth 2.1；ChatGPT 通过授权码 + S256 PKCE 获取 Token，服务端必须逐请求验证授权。[官方授权说明](https://developers.openai.com/plugins/build/auth)

## 分享给独立账号的朋友

1. 在 OpenGym 管理后台点击 **New code**，生成一次性邀请码并复制注册链接；已有未用邀请码旁也有 **Copy invite link**。链接形如 `https://gym.example.com/#/?invite=…`。朋友打开后选择“创建新个人资料”，邀请码自动填入。链接只预填，不自动注册或登录；API 仍验证并消费邀请码。邀请码放在 URL fragment 中，不进入 HTTP 请求或访问日志。不要用“配对手机”或“添加设备”的码邀请朋友注册，否则可能连接到现有账号。
2. 朋友在 [OpenGym](https://gym.example.com/) 注册新账号，确认自己的 App 中是自己的训练数据。保留 `INVITE_ONLY=1`，朋友不加入 `ADMIN_UIDS`，也不授予管理员权限。
3. 朋友在自己 ChatGPT 网页的 Plugins 里选择“添加自定义 MCP 服务器”，填写 `https://gym.example.com/api/plugin/mcp`，身份验证选 OAuth，创建自己的个人插件连接。这复用同一服务，不复用你的授权。[官方接入步骤](https://developers.openai.com/plugins/quickstart)
4. 在 OAuth 页登录朋友自己的 OpenGym 账号，核对账号名称与权限后同意。安卓原生 App 需通过自己的网页账号生成配对码，连接同一服务器。先对 ChatGPT 说“检查当前连接的 OpenGym 账号”，核对 `get_profile` 返回的名称，再读取计划、预览并保存一项测试修改，在自己的 App 中核对；同时检查你的账号数据不变。
5. 可通过 [OpenGym 授权管理](https://gym.example.com/api/plugin/connections) 撤销自己的连接；“退出全部设备”也会使该用户的已有授权失效。

可将 [朋友接入说明页](https://gym.example.com/api/plugin/connect) 一并发给朋友。此页不会自动安装插件或授予访问权。若已有插件连接未出现 `get_profile`，在 ChatGPT 插件管理页刷新工具并开启新聊天；本版没有增加 OAuth scope，现有授权保留。

`get_profile` 是经过 OAuth 保护的只读工具（`plan:read`），只返回当前连接账号的稳定 ID、名称和显示标签，使用官方 `_meta["openai/profile"]` 与 `outputSchema`/`structuredContent` 约定。不提供其他用户列表、邮箱、管理员标记、凭据或训练数据。它帮助用户辨识连接；真正的隔离仍由每次调用的 Token 验证及账号范围检查保证。[官方账号识别约定](https://developers.openai.com/plugins/build/auth)

**插件分发与数据权限是两回事。** 官方说明工作区发布只能供对应工作区成员使用；不属于该工作区的独立账号不能因此访问插件。[工作区发布范围](https://developers.openai.com/plugins/build/plugins)

因此，不能把现有个人插件的目录链接视为已验证的跨账号安装邀请。少量朋友优先各自创建同一 MCP 的个人连接，前提是其账户具有该入口。若需要人人直接点击目录链接安装，可走公开目录审核发布；这会公开插件的可发现性，私有数据仍由各人的 OAuth 授权保护。官方建议私人或工作区使用选择自定义 MCP，公开提交则面向公开分发。[官方分发要求](https://developers.openai.com/plugins/deploy/app-review)

## 服务端隔离约束

### Reconnect 与重复授权

重连修复已于 2026-10-18 21:54（UTC+8）部署，镜像、备份和回退记录见 OPERATIONS.md。

- 点击“同意授权”只生成一分钟有效的一次性授权码，不立即新增持久授权。未返回 ChatGPT、取消或兑换失败，不占用连接名额，也不会替换原连接。
- ChatGPT 通过 PKCE 校验并兑换新凭证时，替换同一 OpenGym 用户、同一 OAuth `client_id` 的全部旧授权及旧 Token。历史重复授权也在此时清理，原本已累计十条重复授权的客户端仍能重连。
- 新授权只包含此次同意的权限；不把旧权限合并进来。其他 OpenGym 用户和不同 OAuth 客户端的授权保留。
- 每个用户最多连接十个不同 OAuth 客户端；重复重连同一客户端不额外占位。兑换时再次检查容量与账号状态。
- OAuth 客户端不能等同于手机或 ChatGPT 账号。若多个 ChatGPT 安装使用相同 `client_id` 并连接同一 OpenGym 用户，成功重连会使它们使用的旧凭证失效。旧授权下尚未保存的草稿需要重新预览。
- 授权页会提前说明替换行为；管理页显示授权编号、客户端、中文权限、UTC+8 授权时间与到期时间，最新在前。本站无法确定 ChatGPT 是否最终收到了凭证，也无法识别具体手机。

2026-10-18 22:27（UTC+8）追加授权反馈修复：首次提交禁用按钮并显示处理中；POST 以 303 转向本站结果页，先显示已同意，再通过页面导航返回 ChatGPT，并保留手动返回按钮。同一请求重复提交返回相同结果和授权码，不重新生成授权。只有兑换成功才显示连接已完成；过期结果明确说明未完成兑换。结果页仍检查登录用户、会话版本，提交仍检查同源与 nonce。表单改用 strict-origin，避免 no-referrer 导致浏览器表单发送 Origin: null，不放宽同源校验。

`oauth-reconnect.test.js` 覆盖失败和放弃的重连、重复提交、相同结果复用、完成与过期结果、旧授权清理、权限缩减、账号和客户端隔离、容量、会话失效及持久化失败回滚。原有多授权隔离测试使用不同注册客户端保留独立连接语义。

| 边界 | 当前实现 |
|---|---|
| 身份 | 访问 Token → 有效授权 → `uid` → 当前仍存在且未禁用的用户；校验授权期限及 session version |
| 读取 | 按授权用户读取 `state-<uid>.json`，再从该状态查模板、训练、版本及自定义动作；没有枚举其他用户的工具 |
| 写入 | 草稿同时绑定 `uid` 和 OAuth grant；同一用户的另一次授权也不能保存旧授权的草稿 |
| 文件持久化 | 最后写入前再次检查草稿 `uid` 等于当前用户，用户仍存在且未被禁用；管理员也不能跨账号保存 |
| 对象 ID | 相同模板/训练 ID 在各自账号状态内解析；猜到别人独有的训练/版本/自定义动作 ID 不授予访问权 |
| 伪造身份 | query、工具参数、`X-User-ID` 或浏览器 Cookie 不能覆盖 MCP Bearer 的账号；只有 Cookie 不能调用受保护工具 |
| 权限 | Plugin Token 不被网站的登录和管理员 API 接受；Plugin 没有账户/管理员工具 |
| 授权管理 | 页面仅列出本人授权；撤销操作验证同源、CSRF、登录用户与授权归属 |
| 公共信息 | 匿名动作检索只搜索公共动作目录，不返回其他用户的自定义动作或训练数据 |

隔离不依赖模型遵守文字指令。未授权、授权撤销或身份校验失败时拒绝访问，不回退到所有者/默认账号。

**隐私范围：** 朋友作为普通用户及其 Plugin 不能查看你的信息；你的 Plugin 同样只访问自己的账号。不过 OpenGym 原有管理员后台可查看用户训练与体重，服务器运维者也能读取数据文件。本轮没有将系统改成“管理员也无法读取其他用户数据”的端到端加密系统，应向朋友说明这个既有边界。

## 验证

```sh
npm test --prefix api/plugin
```

19 项 Plugin 测试在本地及服务器 Linux 隔离容器通过；60 项 API 登录/通行密钥/同步相关测试和 91 项前端邀请链接/远程连接/同步测试通过。前端生产构建通过，浏览器实际验证邀请提示和填码表单。公网检查确认新网页 bundle 包含注册链接功能，接入说明可匿名访问且不显示登录账号。`api/plugin/test/account-isolation.test.js` 启动实际 `api/server.js`，用临时目录中的管理员 Alice 和普通用户 Bob，完成各自 OAuth、实际 HTTP MCP 调用与真实状态文件写入，覆盖：

- 所有私有读取工具的双向隔离；相同记录 ID、伪造身份参数、冲突 Cookie 和请求头不改变账号。
- 猜测其他账号的训练、模板、版本和自定义动作 ID 被拒绝。
- 三种保存工具双向拒绝跨用户草稿；拒绝同用户跨授权保存；保存和重复保存后 Alice 文件字节完全不变，Bob 的修改仅出现在 Bob 文件中。
- 普通用户不能读管理员接口，管理员的 Plugin Token 也不能调用管理员接口。
- 授权列表和撤销请求隔离；撤销 Alice 不影响 Bob；Bob Token 刷新仍保持账号范围，退出全部设备后访问和刷新均失败。
- 邀请只能由管理员生成；无邀请码不能申请注册。旧授权页 nonce 被刷新后的页面作废，避免旧表单批准后来切换的账号。
- `get_profile` 的结构化返回及刷新后的稳定账号身份；未授权的账号识别调用被拒绝。
- 两个账号分别生成并兑换一次性手机配对码，使用真实手机 Bearer 读取 `/api/data`；Bob 的 Plugin 保存结果能同步到 Bob 手机，Alice 手机仍只读 Alice 数据。

自动化测试验证的是服务端及手机同步协议，不代替朋友账户的插件安装权限、Android 原生 UI 或 ChatGPT 端真实保存验收。
